# Cloudflare R2: storage for every recording

Supabase holds rows; R2 holds files. R2 has no download (egress) fees and takes files of
any realistic size (multipart, up to about 5 TB per object).

## One-time setup (about five minutes)
1. Cloudflare dashboard → **R2 Object Storage** → **Create bucket**.
   - Name: `mmos-media`. Location: **Automatic**, with a hint of **Western Europe** (near the database and workers).
   - If you choose the **EU jurisdiction**, set `R2_JURISDICTION=eu`.
2. Bucket → **Settings** → **CORS policy** → paste:
   ```json
   [
     {
       "AllowedOrigins": ["https://multi-media-os-studio.vercel.app", "http://localhost:3200"],
       "AllowedMethods": ["PUT", "GET", "HEAD"],
       "AllowedHeaders": ["*"],
       "ExposeHeaders": ["ETag"],
       "MaxAgeSeconds": 3600
     }
   ]
   ```
   `ExposeHeaders: ETag` matters: the browser needs each part's ETag to finish the upload.
3. R2 → **Manage API tokens** → **Create API token** → permission **Object Read & Write**,
   applied to `mmos-media` only. Copy the Access Key ID and Secret Access Key (shown once).
4. Put them into **Vercel → multi-media-os-studio → Settings → Environment Variables** (and later Railway):
   `R2_ACCOUNT_ID` (from the R2 overview page), `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET=mmos-media`.
   Never paste them into chat or commit them.
5. Redeploy the Studio. The Upload page opens once these are present.

## Lifecycle (recommended)
Bucket → Settings → **Object lifecycle rules** → abort incomplete multipart uploads after 7 days,
so cancelled uploads never leave paid-for fragments behind.
